# 日制战争设计与实施

目标：将既有全球历史开局游戏改为持续作战的轻量指挥游戏，师级兵力接近历史量级，日常操作围绕出征、同盟与部队。用户选择按日推进；月底结算现有工业、研究、训练与事件。保留历史开局＋自由推演。

参考：[Paradox 官方战略指南](https://forumcontent.paradoxplaza.com/public/paradox/banners/HoI_IV_Strategy_Guide.pdf)、[官方游戏介绍](https://www.paradoxinteractive.com/games/hearts-of-iron-iv/about)。指南强调组织度决定持续作战与撤退，补给影响大军效率，军队组织和战斗计划连接进攻、防守、空军与海军。采用这些原则，使用本项目的原创轻量规则与界面。

方案选择：保留月制、另开战斗小回合容易出现两套时钟；完全复制原作的模板、逐小时宽度和复杂后勤不适合当前节点地图。采用一个日制时钟、目标式作战计划、预设兵种和自动后勤，保留影响战果的决策。

## 玩法循环

1. 前线给出实际可攻击目标及出发地；选择目标查看部队、地形与支援，确认下达出征命令。
2. 出征只开始准备阶段，不改变控制权。至少数天后持续战斗；双方消耗组织度和实力，正面宽度限制投入，多余兵力进入预备队。
3. 玩家可暂停、按日推进、切换谨慎/均衡/强攻、调入真实邻近增援、请求已参战盟友支援、撤退；防守方同样可以下命令。兵力不可重复投入。
4. 组织度崩溃或突破才结算局部战斗。守军有安全路线时撤退，围困时损失部队。首都失陷只影响投降进度；主要胜利节点丧失达到阈值才投降。
5. 部队在后方休整，补充实力消耗装备和人力；生产、科技、国家建设仍按月结算，不因日制重复发放收入。

## 原作功能的轻量对应

| 重要功能 | 本项目对应 |
|---|---|
| 组织军队与战斗计划 | 战略节点驻军汇总、推荐目标、出征数量、多方向增援，替代手绘长箭头 |
| 组织度与战斗实力 | 分开显示并在持续战斗中损耗；战术影响推进和伤亡 |
| 正面与预备队 | 地形限制正面投入，更多师提供轮换和持续力 |
| 空军、舰队与登陆 | 继续使用航程、军种、反舰与制空支援；登陆需要实际港口和海路 |
| 增援、补给、休整 | 合法增援来源、实际储备与基础设施、资源补充 |
| 同盟与共同作战 | 结盟、召集参战、防御同盟、已参战盟友实际投入邻近部队 |
| 生产、研究、建设 | 保留原系统和全部十八种兵种，默认自动后勤，管理菜单可手动控制 |
| 投降、议和、存档 | 战略节点投降进度、和平清理交战；存档保存正在交战的状态 |

师模板使用预设军种；政治/外交、海陆空、建设、研究均保留入口。历史师数注明日期、来源、估算口径；海空单位仍为编队抽象，不伪称每枚图标是一艘船或一架飞机。

## 界面边界

常显三个入口：前线、军队、同盟；暂停与推进一天常显。后勤、任务、存档和主界面放入管理菜单；地图模式折叠。交战时优先展示一个战斗卡，其余战斗用选择框切换，其他进攻目标折叠；默认动作只给增援与撤退，战术用选择框。

地图只用局部可点击交战标记及出发/目标圆环，不恢复战线、海路线和攻击长连线。军队按省区/军种合并显示，不按数百个师创建按钮。

## 实施和验证分工

- 兵力模块：新增 `js/order_of_battle.js` 与来源说明；按当前控制权部署陆军，保留海空编队；新开局应用，旧存档不凭空扩军。
- 战斗引擎：修改 `js/game.js`，持久战斗与日制时钟，统一玩家和 AI；验证邻接、锁定、增援、撤退、投降、和平和存档。
- 指挥界面：修改 `js/ui.js`，绑定真实战斗接口；所有推进入口统一按日，保持已展开选项与当前交战选择。
- 集成：根代理负责导航、样式、地图标记、加载顺序、文案、实际浏览器验收与独立代码审核。

必要验收：下令后不立即占领；推进后状态变化；战术、增援、撤退和盟友支援真实影响部队；不能同时投入两场战斗；月末只结算一次；交战保存恢复一致；失去首都不无条件投降；大军队不增加地图线条或逐师按钮；桌面与窄屏可完成命令；新标签正常加载。
