# v45 战争指挥设计与验收

## 设计

默认只显示战场、双方实际人数、行军/突破阶段和直接命令。战术改为三个按钮；选择战术即执行并恢复选定速度，战场卡内可执行/暂停，不需要寻找顶栏。出征前可选战术、确认后自动行军。必选事件和敌方进攻警报必须处理后才推进。补给、师数、计算、伤亡、自动策略和完整战报按需打开。

按钮区采用暖金主命令与深青次命令、明确选中/禁用/焦点状态；核心正文 16 px，触摸命中至少 44 px。默认信息减少，保留必要的出击/留守兵力与宣战代价。

陆路查询统一使用真实省区图，累计途中距离；中间城市仅允许本国或直接盟友，不通过敌国、中立国、海洋或盟友的盟友。路权变化安全取消，远程增援抵达前不投入战宽与火力。

法国90省、波兰17区、德国30个历史邦/省、英国101个历史郡成为独立控制节点，德国/英国较大飞地单列为43/116个作战区，全图470区。旧档保留原节点索引与真实部队，扩展其余子省的控制权，不复制兵力。来源、年份与未覆盖范围单列，避免用现代行政区冒充历史边界。地图默认只显示关键城市与当前前线地名，完整省名点选或悬停查看。

## 必须核验

- 新玩家从战局选择目标、战术、确认进攻后看到实际行军；战场内战术、暂停、增援和必选警报。
- 直接/多段本国/盟友路线，以及中立、敌方中间点、海路、退盟、失守、读档和单位守恒。
- 实际历史数据覆盖内的地图填色、点击、国界和路线一致；各城市自点击、真实开局兵力规模/前线分配。
- 桌面、平板横/竖屏、窄屏的默认可见信息、按钮命中及无遮挡；按压跨日、取消和双指缩放回归。
- 全量 JavaScript、Python 服务测试、语法、diff 格式；完整本地提交、固定原网址版本/提交/资源指纹与缓存验证。

## 本地验收结果

- 305项JavaScript回归全部通过；Python服务器2项通过；JavaScript语法与`git diff --check`通过。
- 用网页实际12个核心脚本运行1939战役60日，40场战斗，单位ID无重复、人数账本一致、保存恢复成功。开局与第60日均1205个单位对象，德国103个陆军师；全国军队与行政权重守恒另由专门回归验证。60次每日逻辑共989.72ms，最大单日52.45ms；这是本机VM逻辑耗时，不等同于平板渲染性能。
- 浏览器实际确认进攻后自动行军并推进日期；法国进攻出现持久警报并暂停，处理警报后点击战术恢复推进。卡片内执行/暂停均可操作。真实地图点击分别打开巴伐利亚本部和新增黑森省，显示各自独立指挥卡。
- 浏览器1280×800、1024×768、768×1024、390×844无横向溢出。可见导航及关闭命中44px，战术48px，执行52px，中心命中均未被遮挡；核心字体16px、执行18px。触摸按压跨刷新、拖动取消与双指缩放使用Pointer回归，尚无实体平板或Safari实机验收。
- 发布由完整提交的post-commit钩子运行全量测试、资源指纹构建、固定Netlify生产部署及`version.json`/`hoi-build`/缓存验证。正式页面仍需部署后浏览器验收；部署命令的终端结果作为正式版本凭据。
