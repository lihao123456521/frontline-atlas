# 战争优先 Implementation Plan

> **For agentic workers:** Use superpower-subagents to implement the bounded tasks; retain existing edits and do not commit or publish.

**Goal:** 把打仗与同盟放在主流程，自动后勤减少重复操作。
**Architecture:** 复用现有 Game 与 UI；game.js 提供统一外交可用性、参战与后勤 API，ui.js 改现有战争/训练/外交视图；index 与新增 CSS 简化导航。保留历史地图、命令确认与旧档。
**Tech Stack:** 原生 JavaScript、SVG、CSS、node:test、真实 IAB 浏览器。

## 引擎（game.js、tests/war-support.test.cjs）
- [x] 先加入结盟一次扣费、敌我关系互斥、陆战/登陆拒绝盟友、盟友参战和实际 AI 共敌战斗的失败测试。
- [x] 提供 diplomacyAvailability(action,targetId,enemyId)、callAlly(targetId,enemyId)，UI 与引擎用相同条件。结盟保持防御同盟，进攻战争用召集参战；拒绝将盟友拖入对其盟友的战争。
- [x] 提供 setAutoLogistics(enabled)、autoLogisticsStatus()。新档默认开启、旧档兼容；每月贸易、军事研究和基础增援按储备与队列限额执行。关闭后不自动消费；记录理由和支出，不自动开战。
- [x] 测试通过后交付 API 与证据。

## 交互（ui.js、tests/war-ui.test.cjs）
- [x] 前线复用 war 视图，显示敌军/可用出击/目标，点击定位与计划进攻，保留确认和取消。
- [x] 军队复用 production 视图，常用训练优先，其他兵种折叠；工业建设放入后勤 logistics。
- [x] 同盟复用 diplo 视图，筛选国家、显示盟友优先、结盟/改善关系/召集/确认宣战/单独议和明确条件；使用引擎可用性原因。
- [x] 后勤包括自动开关、自动行为/库存不足反馈，以及手动经济、研究、国策入口；任务保留次级入口。
- [x] 实际 Game 状态的 DOM 回归验证新入口和确认不会自行扣费/发起战斗。

## 外观与集成（index.html、css/war-command.css、README）
- [x] 主导航为前线、军队、同盟；后勤与任务次级。按钮字面表达动作，压缩非战争信息。
- [x] 浏览器验证前线选择/确认/取消、同盟操作与后勤开关；保存实际截图。提高缓存版本。
- [x] 跑完整 tests、语法及 diff 检查，只修新失败；外壳独立审核，引擎/UI 额度不足后由主代理按角色分离审核，详见验收记录。
